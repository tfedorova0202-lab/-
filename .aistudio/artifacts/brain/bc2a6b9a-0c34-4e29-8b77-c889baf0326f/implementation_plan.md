# ЮрПомощник: Очистка CI/CD и интеграция Firebase (Auth & Firestore)

Комплексный план по устранению конфликтов и синтаксических ошибок в `.github/workflows/`, стабилизации пайплайна автоматической сборки Android APK, а также подключению авторизации через Google Sign-In и облачной синхронизации реестра долгов в Firebase Firestore с соблюдением требований 152-ФЗ и режима «Инкогнито».

---

### User Review & Critical Decisions

> [!IMPORTANT]
> **Принятые решения на основе выбора пользователя (Первый кейс):**
> 1. **Очистка GitHub Actions**: Удаление всех фрагментарных, несовместимых (.NET, Go) и поврежденных файлов из каталога `.github/workflows/`, сохранение и оптимизация единого надежного рабочего процесса `build-apk.yml`.
> 2. **Авторизация и база данных**: Подключение официального Firebase Auth (Google Sign-In через Jetpack `CredentialManager`) и облачной базы данных Firestore для синхронизации реестра долгов и расчетов.
> 3. **Безопасность и защита семьи (152-ФЗ & Инкогнито)**: Включение маскирования персональных данных (ФИО, паспортные данные, номера кредитных договоров) при синхронизации в облако, обеспечение полной конфиденциальности перед третьими лицами и родственниками.

---

### 1. Overview & Core Concept

- **Что решает обновление**:
  - Устраняет критические ошибки и поломки пайплайна GitHub Actions, вызванные некорректным добавлением разрозненных сниппетов (без структуры `on`, `jobs`, с ошибками расширений файлов и сторонними стеками .NET / Go).
  - Обеспечивает безопасное облачное сохранение расчетов («План / Факт», реестр долгов, отмененные штрафы по ст. 333 ГК РФ и лимиты переплат МФО) с привязкой к Google-аккаунту пользователя.
  - Сохраняет полный функционал локального офлайн-доступа и ручного сброса данных в один клик.

- **Целевая аудитория**:
  - Должники, заемщики банков и МФО, которым необходима юридическая защита, перерасчет начислений и уверенность, что их данные не потеряются при смене устройства, но останутся строго конфиденциальными.

### 2. User Experience & Visual Design

- **Экран авторизации (Auth Gate)**:
  - При первом запуске или выходе из аккаунта пользователю доступен экран входа с официальной кнопкой **«Войти через Google»** (`GoogleSignInButton`), оформленной по гайдлайнам Google Identity и Material 3.
  - Доступен режим гостевого ознакомления / быстрого перехода к правовой базе знаний, калькуляторам и памяткам.
- **Индикатор синхронизации в Реестре долгов**:
  - В заголовке реестра отображается аккуратный статус облачной синхронизации (облако со стрелками / галочка актуальности).
  - Возможность принудительного обновления свайпом или нажатием кнопки.
- **Профиль и безопасность**:
  - В карточке профиля отображается аватар и email авторизованного Google-аккаунта.
  - Кнопка **«Выйти из аккаунта»** с безопасной очисткой локальной сессии `CredentialManager`.
  - Переключатель «Маскирование персональных данных при синхронизации (152-ФЗ)» (по умолчанию включен).

### 3. Key Product Decisions & Trade-Offs

- **Решение 1: Ликвидация мусорных workflow-файлов**:
  - *Выбранный подход*: Удалить 11 поврежденных файлов и ошибочных каталогов (`.github/workflow/`, `go-ci.yml`, `main.yml`, файлы без расширений), оставив чистый, проверенный `build-apk.yml`.
  - *Почему*: Файлы содержали фрагменты YAML без объявления событий `on:` и джоб `jobs:`, а также стек Go и .NET, которые приводили бы к постоянному падению CI/CD при пушах в репозиторий.
- **Решение 2: Облачная синхронизация Firestore + локальный кэш**:
  - *Выбранный подход*: Двухуровневая модель: локальная база Room + облачный репозиторий `FirestoreDebtsRepository`.
  - *Почему*: Гарантирует бесперебойную работу при отсутствии интернета и мгновенную синхронизацию при появлении сети.
- **Решение 3: Строгая изоляция пользователей в Firestore Security Rules**:
  - *Выбранный подход*: Коллекция `users/{userId}/debts/{debtId}` с правилом `request.auth.uid == userId`.
  - *Почему*: Исключает любую возможность утечки или перекрестного доступа между пользователями.

#### Этапы выполнения:
1. **Аудит и чистка `.github/`**:
   - Удаление каталога `/.github/workflow/` и поврежденных файлов (`App Shield protect`, `Attest Build Provenance`, `Autify for Mobile.yml`, `Mobile Tests.yml`, `Run Parasoft Jtest.yml`, `Run test on Autify for Mobile.yml`, `go-ci.yml`, `javadoc-cleanup`, `main.yml`, `main.yml.github`).
   - Доработка `/.github/workflows/build-apk.yml`: валидация шагов сборки, запуск линтера и тестов, безопасный экспорт APK в артефакты.
2. **Инициализация Firebase**:
   - Извлечение отпечатков SHA-1 / SHA-256 из `debug.keystore`.
   - Инициализация через диалог согласия `show_aistudio_ui(ui_type: "firebase_setup")` и RPC `ProvisionFirebase`.
   - Создание `firebase-blueprint.json` и `firestore.rules`.
3. **Разработка Auth & Firestore слоя**:
   - Подключение `GoogleSignInButton` и `attemptAutoSignIn` на базе `CredentialManager`.
   - Создание `FirestoreDebtRepository` с поддержкой маскирования данных.
   - Тестирование правил безопасности и деплой через `DeployRules`.
4. **Финальная компиляция и проверка сборки**:
   - Запуск `compile_applet` для подтверждения целостности кода и сборки APK.
